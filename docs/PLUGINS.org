#+title: Plugin API

* Goal

=emacs-auto-research= is a standalone Emacs package.  It does not depend on
Consortium, StarIntel, ARADR workers, RAGE, GitHub, or any other workflow
engine/backend.

Those systems can integrate *as plugins*.

A plugin may contribute:

- research projects/control-plane roots;
- a document recognizer slot for future specialized discovery;
- asynchronous external dashboard items;
- integration-specific actions exposed through the unified UI;
- an after-decision callback that observes an explicit local human
  approval/rejection.

The core package remains the authority for canonical approval metadata and the
human-facing decision UX.

* Registering a plugin

#+begin_src emacs-lisp
(require 'auto-research-plugin)

(auto-research-register-plugin
 (auto-research-plugin-create
  :id 'my-workflow
  :project-provider
  (lambda ()
    '((:id my-project
       :name "My Project"
       :root "~/src/my-project"
       :research-root "research")))
  :actions
  (lambda (context)
    (list
     (list :id 'inspect-workflow
           :label "Inspect workflow state"
           :command
           (lambda (context)
             (message "Inspect %s" (plist-get context :file))))))
  :after-decision
  (lambda (file state project)
    (message "Workflow saw %s for %s" state file))))
#+end_src

Project plists returned by =:project-provider= use the same schema as
=auto-research-projects=.  They are merged into the normal dashboard, so plugin
projects do not get a second UI.

Duplicate project IDs fail closed.

* External dashboard providers

=:dashboard-provider= supports sources that are not local files, including the
optional GitHub adapter.

The provider is called as:

#+begin_src text
(PROVIDER SCOPE EMIT DONE)
#+end_src

- =SCOPE= is =all= or the selected local project ID.
- =EMIT= accepts a list of =auto-research-item= objects and may be called many
  times as asynchronous results arrive.
- =DONE= must be called once with nil on success or an error string when the
  source finishes with recoverable failures.

External items are built with =auto-research-dashboard-make-item=.  They should
supply a stable =:id=, display project/path, title/lifecycle/approval, and an
=:open-function=.  A writable backend may also supply =:decision-function=.

A decision function is called as:

#+begin_src text
(DECIDE ITEM STATE ACTOR EVIDENCE DONE)
#+end_src

Its =DONE= callback receives =(OK MESSAGE)=.  This lets remote backends do
asynchronous race checks and durable delivery while the core dashboard owns the
busy state, error reporting, and refresh.

The GitHub backend uses this contract to stream remote research into the same
=M-x auto-research= dashboard without making GitHub a core dependency.

* Plugin actions

The =:actions= provider receives a context plist.

Typical fields are:

- =:source= — =dashboard= or =document=;
- =:file= — absolute local research file path, or nil for an external item;
- =:project= — normalized local =auto-research-project=, or nil;
- =:item= — dashboard item when invoked from the dashboard.

Return zero or more action plists with:

- =:id= — stable action identifier;
- =:label= — human-facing label;
- =:command= — function receiving the context plist.

Users invoke plugin actions with:

| Context | Vanilla Emacs | Doom/Evil |
|---------+---------------+-----------|
| Dashboard | =x= | =x= |
| Open local research document | =C-c C-x= | =x= |

The UI prompts when more than one plugin action is available.

* Consortium integration

Consortium should live in its own repository/package and register an
=auto-research-plugin= from there.

Conceptually:

#+begin_src emacs-lisp
(auto-research-register-plugin
 (auto-research-plugin-create
  :id 'consortium
  :project-provider #'consortium-auto-research-projects
  :actions #'consortium-auto-research-actions
  :after-decision #'consortium-auto-research-after-decision))
#+end_src

That adapter can expose actions like "show run", "resume analysis", or "open
design" and can translate an =APPROVED= local artifact into whatever Consortium
control-plane event is legal under Consortium's own state machine.

The adapter must not make =emacs-auto-research= require Consortium, and the core
package must not encode Consortium phase transitions.

* Authority boundary

Plugins can observe local decisions, contribute projects/items, expose explicit
actions, and implement an external item's own durable decision delivery.  They
must not silently reinterpret or rewrite decisions owned by another backend.

A workflow engine remains responsible for deciding whether a given approval is
sufficient to advance its own state machine.
